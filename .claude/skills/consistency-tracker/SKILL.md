# Consistency Tracker — 一致性追踪

## 工作流

### 第 1 步：提取当前章节实体

```bash
python .claude/skills/consistency-tracker/scripts/extract_entities.py \
  --file chapters/chapter_NNNN.md \
  --chapter N \
  --entity-db .storyai/entity_db.json
```

提取五大类实体：
1. **角色出现记录** — 谁在本章出现了？出现了几次？
2. **地点引用** — 故事现在发生在哪里？
3. **物品/功法引用** — 使用了什么法宝、功法、丹药？
4. **世界规则触发** — 触发了哪些力量体系的规则？（境界突破、力量使用、法则触及）
5. **情节线推进** — 新信息揭露了什么？留下了什么悬念？

### 第 2 步：更新实体数据库

将提取结果合并到 `.storyai/entity_db.json`：
- 新实体 → 新增，记录首次出现章节
- 已有实体 → 更新最后出现章节、累积状态变化
- 状态追踪：角色位置变化、境界变化、生死状态

### 第 3 步：矛盾检测

对以下情况发出警告：

| 矛盾类型 | 检测方式 | 严重度 |
|---------|---------|--------|
| **空间矛盾** | 同一角色在同一章（或相邻章）出现在两个不同地点 | 高 |
| **时间矛盾** | 事件顺序不合理（果在因之前） | 高 |
| **规则矛盾** | 角色使用了超出设定上限的能力 | 高 |
| **角色矛盾** | 性格/行为模式无解释地突变 | 中 |
| **物品矛盾** | 已消耗/丢失的物品再次出现 | 中 |
| **情节线断裂** | 已引入的伏笔长期未再提及（>10 章） | 低 |
| **关系矛盾** | 角色间的关系状态与之前定义不一致 | 中 |

### 第 4 步：生成一致性报告

更新 `consistency_report.md`，包含：
- 本章实体统计
- 新增实体列表
- 状态变化记录
- 矛盾警告（如果有）
- 待解决情节线清单

## 输出
- `.storyai/entity_db.json` — 更新的实体数据库
- `consistency_report.md` — 增量更新的一致性报告

## 约束
- 只检测和报告，不修改章节内容
- 矛盾检测用规则引擎（脚本），复杂的语义判断由 Claude 完成
- 对于不确定的矛盾，标记为"疑似"而非"确定"，留给用户判断
